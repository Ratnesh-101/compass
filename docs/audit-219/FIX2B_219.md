## 2. Detailed Task Walkthrough

### TASK 1: False Negatives Resolution & Trailing Apostrophe Quote Edge

1. **Root Cause Analysis**:
   - Word/verb typos (`ad`, `craete`, `shedule`, `remnd`, `taks`, `tsak`, `mee`, `tomorow`) failed exact prefix and keyword lookups in `router_helpers.py` and `task_intent.py`.
   - Hinglish imperative phrasing (`mujhe remind kar dena`, `ek task add kar do`, `yeh task list me daal do`, `remind me ki ... kal`) placed verbs after nouns or used Hindi connectors (`ki`, `kal`) which failed standard English regexes.
   - Polite question commands like `"Would you mind creating a deadline for project demo on Friday?"` were stripped of `"Would you mind creating "` by neither `_POLITE_PREFIX` nor Strategy D prefixes, leaving empty titles and being classified as questions.
   - In `_strip_quoted_text`, any apostrophe not followed by an alphanumeric character toggled `in_single = True`. For trailing apostrophes (`the users' tasks`, `my parents' birthday`), this treated the entire remainder of the message as a single-quoted span and blanked out the task words.

2. **Remediation**:
   - Implemented `normalize_task_intent_text(text: str)`:
     - Handles polite `"would you mind (adding|creating|setting|scheduling)"` prefix.
     - Maps Hinglish patterns (`mujhe remind kar dena to` -> `remind me to`, `ek task add kar do` -> `add task`, `task list me daal do` -> `add task`, `daal do` -> `add`, `remind me ki` -> `remind me to`, `kal` -> `tomorrow`).
     - Replaces closed dictionary typos: `taks`/`tsak`/`tak` -> `task`, `ad`/`aad` -> `add`, `craete`/`creat`/`crate` -> `create`, `shedule`/`schedual` -> `schedule`, `remnd`/`remid` -> `remind`, `mee` -> `me`, `tomorow` -> `tomorrow`.
     - Applies `difflib.get_close_matches` with `cutoff=0.8` strictly bounded to the single first word and noun word (checked within the first 4 tokens), skipping non-noun stop words.
   - Fixed `_strip_quoted_text`:
     - Identified `is_word_apostrophe = i > 0 and text[i - 1].isalnum()`.
     - When `not in_single`, if `is_word_apostrophe` is true, appends the apostrophe without toggling `in_single`, preventing trailing apostrophes on words from opening quote spans.
   - Maintained all question, opinion, discussion, and capability guards (`can you add tasks?`, `kya tum add task kar sakte ho?`, `Did you remind me...`, `Should I add a task...`, quoted speech).

### TASK 2: Timezone DST Gap & Fallback Behavior

1. **DST Spring-Forward Gap (`America/New_York` 2026-03-08 02:30)**:
   - On March 8, 2026, clocks in New York jump from 02:00:00 EST directly to 03:00:00 EDT.
   - `combine_local` computes `2026-03-08 07:30:00+00:00` (UTC), which converts to `03:30:00 EDT`.
   - Behavior kept as documented standard roll-forward.
   - Replaced assertion in `tests/test_audit_timezone.py::test_dst_spring_forward_gap_preserves_local_clock_time` with `assert due_at == datetime(2026, 3, 8, 7, 30, tzinfo=timezone.utc)` and checked local EDT clock time `03:30:00`.
   - Removed `@pytest.mark.xfail` marker.

2. **DST Fall-Back Ambiguous Instant (`America/New_York` 2026-11-01 01:30)**:
   - 01:30 AM occurs twice on November 1, 2026 (first EDT UTC-4 = 05:30 UTC, then EST UTC-5 = 06:30 UTC).
   - Python's `datetime.combine` defaults to `fold=0`, which correctly selects the first (EDT) occurrence.
   - Added `test_dst_fall_back_ambiguous_time_pins_first_occurrence_edt()` verifying `due_at == datetime(2026, 11, 1, 5, 30, tzinfo=timezone.utc)` and `local_dt.tzname() == "EDT"`. No crash observed; `backend/services/task_time.py` unmodified.
