## 2. Detailed Changes per Task

### TASK 1 — BUG-02: Tasks Committed Before Request Log (Atomic Idempotency)
- **Problem**: When a mutating task request was committed by `structured.create_task`, any subsequent failure in post-creation processing (e.g. `format_tool_response`, audit logging, or message history persistence) aborted the request. In `chat_idempotency.py`, `_finish(..., result=None)` was executed, deleting the pending claim from `chat_request_log`. On retry with the same `request_id`, the request was re-executed from scratch, encountering a duplicate error (`duplicate_exact_deadline`).
- **Files and Line Ranges Changed**:
  - [`backend/services/chat_idempotency.py:12,78-111,128,147,168-179,230,248`](file:///C:/Users/Ratnesh%20Singh/OneDrive/Desktop/compass-chat-task-intake/backend/services/chat_idempotency.py#L78-L111):
    - Added `_committed_outcome: contextvars.ContextVar[Optional[Dict[str, Any]]]`.
    - Added `record_committed_outcome(...)` helper storing minimal committed outcome (reply text, `status = "committed"`, `task_ids`, `data`, `skill_used = "add_task"`).
    - Updated `_claim` and `peek_replay` to select and replay entries where `state in ('done', 'committed')`.
    - Updated `_finish` so when `result is None` (exception path) but `_committed_outcome.get()` is present, it executes `UPDATE chat_request_log SET state = 'committed', response = $3::jsonb ...` instead of `DELETE FROM chat_request_log`.
    - Initialized and reset `_committed_outcome` per request in `run_chat_request`.
  - [`backend/orchestrator.py:789-796`](file:///C:/Users/Ratnesh%20Singh/OneDrive/Desktop/compass-chat-task-intake/backend/orchestrator.py#L789-L796):
    - Replaced the 12-line multi-line argument block of `structured.create_task` with a compact 4-line invocation and called `record_committed_outcome(task_record, conv_id=conv_id)`. Net line count decreased from 1,103 to 1,098 lines (meeting the grandfathered file limit).

### TASK 2 — BUG-07: Hard-Coded Fallback HMAC Secret Removed & Fail-Closed Protection
- **Problem**: `backend/config.py:61` hard-coded a default 36-character HMAC secret (`compass_vercel_edge_hmac_secret_2026`). If `EDGE_HMAC_SECRET` was omitted from the environment, requests were validated against this known secret. In `frontend/middleware.js`, an unset secret caused requests to fail open and be forwarded unsigned.
- **Files and Line Ranges Changed**:
  - [`backend/config.py:13-16,64,134-150`](file:///C:/Users/Ratnesh%20Singh/OneDrive/Desktop/compass-chat-task-intake/backend/config.py#L64):
    - Changed default `EDGE_HMAC_SECRET: str = ""` (field default length = 0).
    - Generated module-scoped `_PER_PROCESS_DEV_EDGE_SECRET: str = secrets.token_hex(32)`.
    - Added `@model_validator(mode="after")` to populate `self.EDGE_HMAC_SECRET` with `_PER_PROCESS_DEV_EDGE_SECRET` in non-production environments when unset.
    - Updated `is_production()` to check `RENDER` environment variable along with `ENVIRONMENT`.
    - Added `validate_edge_hmac_secret(self)` startup guard raising `RuntimeError("STARTUP REFUSED: EDGE_HMAC_SECRET environment variable is missing in production")`.
  - [`backend/main.py:106,114-115`](file:///C:/Users/Ratnesh%20Singh/OneDrive/Desktop/compass-chat-task-intake/backend/main.py#L106):
    - In `lifespan`, called `settings.validate_edge_hmac_secret()` during startup and re-raised `RuntimeError(f"STARTUP REFUSED: {e}")` if `validate_production_secrets()` fails in production.
  - [`frontend/middleware.js:4,12,40-67`](file:///C:/Users/Ratnesh%20Singh/OneDrive/Desktop/compass-chat-task-intake/frontend/middleware.js#L40-L67):
    - Generated per-process fallback `const devFallbackSecret = crypto.randomUUID()`.
    - Detected production via `VERCEL_ENV`, `NODE_ENV`, `ENVIRONMENT`, or `ENV`.
    - When `secret` is unset in production, returned `Response(JSON.stringify({ error: 'EDGE_HMAC_SECRET environment variable is missing in production' }), { status: 500, headers: { 'content-type': 'application/json' } })`.
    - In non-production, used `devFallbackSecret` so local dev and test executions continue signing and functioning.
  - [`tests/test_round5_hardening.py:83-88`](file:///C:/Users/Ratnesh%20Singh/OneDrive/Desktop/compass-chat-task-intake/tests/test_round5_hardening.py#L83-L88):
